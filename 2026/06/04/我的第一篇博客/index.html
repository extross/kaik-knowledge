摆脱传统 Keil，在 VSCode 上开发 STM32

告别笨重的 Keil IDE，拥抱现代化的开发体验。

一、为什么要离开 Keil？

  • Keil 的编辑器功能落后，代码补全、跳转体验差
  • IDE 本身很卡，打开项目慢、编译时容易卡死
  • 界面丑陋，主题单一，长时间编码视觉疲劳
  • 项目文件 .uvprojx 是二进制格式，不便于版本管理
  • 收费商业软件，有代码大小限制（32KB 免费版）
  • 只支持 Windows，而现在工作中 Linux 已经是主流开发环境，VSCode + GCC + CMake 这套组合才是大势所趋
  • 缺乏现代插件生态（Git 集成、AI 辅助、远程开发…）

总结：Keil 的编译器不错，但 IDE 体验确实跟不上时代了。

二、VSCode 开发 STM32 的两条路

主流有两种开发方式：

方案一：EIDE + Keil 工具链 方案二：GCC + CMake
编译器 Keil 的 ARMCC（需安装 Keil） ARM GNU GCC（完全免费开源）
构建工具 EIDE 插件自动管理 CMake + Makefile
CubeMX 配合 生成代码，EIDE 导入 生成代码 + Makefile
优点 保留 Keil 编译器，接近原厂体验 完全脱离 Keil，全开源工具链
缺点 仍需安装 Keil（要它的编译器） 编译优化可能略逊于 ARMCC（但其实平时用 Keil 我们也不开优化，所以影响不大）
适合人群 已有 Keil 项目、想快速迁移到 VSCode 追求全开源、跨平台的开发者

三、方案一：EIDE + Keil 工具链 + CubeMX

3.1 环境准备

  1. 安装 Keil MDK（只需要编译器，不需要用它的 IDE）
  2. 安装 STM32CubeMX
  3. VSCode 安装插件：EIDE
  4. EIDE 配置 Keil 编译器的路径

3.2 项目创建流程

  1. 用 CubeMX 生成初始化代码（时钟树、外设配置）
  2. VSCode 中 EIDE 插件 → 新建项目 → 导入 CubeMX 生成的代码
  3. EIDE 自动识别 .uvprojx 或手动配置 include path、宏定义
  4. 编译、烧录、调试一键完成

3.3 优势

  • 保留 Keil ARMCC 编译器，编译产物和 Keil 完全一致
  • EIDE 插件对 Keil 项目兼容性好
  • 学习成本低，适合过渡期用户

四、方案二：GCC + CMake（完全脱离 Keil）

4.1 环境准备

安装：

  • ARM GNU GCC 工具链 → ARM 官网下载
  • CMake + Ninja（或 MinGW Make）
  • OpenOCD（调试烧录）
  • STM32CubeMX（生成 HAL 库代码 + Makefile）

VSCode 插件：

  • C/C++（Microsoft）
  • CMake Tools（Microsoft）
  • Cortex-Debug（调试）
  • clangd（可选，智能补全）

4.2 项目创建流程

  1. CubeMX 配置

    • 选择芯片型号，配置时钟和外设
    • Project Manager → Toolchain 选 Makefile
    • 生成代码

  2. CMake 改造（我推荐 CMake 替代裸 Makefile）

    • 编写 CMakeLists.txt（链接脚本、启动文件、HAL 库源文件、include 路径）
    • 配置交叉编译器 arm-none-eabi-gcc
    • 配置编译选项（-mcpu=cortex-m4、-mthumb 等）

  3. VSCode 配置

    • .vscode/c_cpp_properties.json：配置头文件路径和编译器
    • .vscode/launch.json：配置 Cortex-Debug 调试
    • .vscode/tasks.json：配置构建任务

4.3 编译 & 烧录

4.4 调试配置（Cortex-Debug 插件）

  • 使用 ST-Link / J-Link / DAP-Link
  • 断点、变量查看、寄存器、调用栈 → 和 Keil 调试体验一致甚至更好
  • 支持 RTT Viewer（实时日志输出）

五、两个方案的对比总结

维度 EIDE + Keil GCC + CMake
安装复杂度 较高（需装 Keil） 中等
编译速度 中等 快（Ninja 并行）
代码体积优化 较好（ARMCC） 不错（-Os）
跨平台 仅 Windows Windows / Linux / Mac
开源 部分 完全开源
社区资源 EIDE 作者维护 大量开源项目可参考
CI/CD 支持 困难 天然支持（GitHub Actions）

六、我的建议

  • 如果只是尝鲜，先用 EIDE + Keil 方案，学习成本低
  • 如果想彻底告别 Keil、追求跨平台、方便 CI/CD，选 GCC + CMake
  • 学生的 F103/F407 项目完全够用——而且说实话，平时 Keil 默认也是 -O0，没几个人开优化，所以 ARMCC 和 GCC 的优化差距在日常开发中几乎感受不到
